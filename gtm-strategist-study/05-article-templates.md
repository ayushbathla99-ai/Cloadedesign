# 05 — Article Templates (Fill-in-the-Blank Blueprints)

Eight blueprints reverse-engineered from the GTM Strategist archive. Each one lists the posts it was derived from, the beat-by-beat structure with word budgets, and a fill-in skeleton. Target 900–1,800 words for LinkedIn.

---

## T1 — Named Framework
*Derived from:* "Before there is Ideal, there is Early (Customer Profile)" (211♥), "One Page, <20 min" (168♥), "Go-to-Market Milestones" (83♥), "4 GTM Frameworks…" (59♥)

| Beat | Words | Content |
|---|---:|---|
| Hook | 80 | Familiar concept everyone uses → "The problem is…" reframe |
| Origin | 80 | Where the framework came from (N clients, pattern you noticed) |
| Promise | 50 | "In this article, you'll learn:" 3 bullets |
| The framework | 300 | Name + visual/table + 1-line definition of each part |
| Walkthrough | 400 | Each part: what it is → common mistake → how to do it |
| Example | 200 | One real application with numbers |
| Template | 80 | "Copy this:" table/checklist |
| Where I stand | 60 | When to use it, when not to |
| Question + P.S. | 50 | Self-diagnostic question, next asset |

```markdown
# [Before there is X, there is Y] / [The {Name}: {Outcome}]

You've probably heard of [familiar concept]. [One-line common definition].

The problem is [why it fails in reality]. [One-line twist].

After [doing X with N teams/clients], I kept seeing the same pattern: [pattern].
So I gave it a name: **[Framework Name]**.

**In this article, you'll learn:**
- **What [Framework] is** and why [familiar concept] isn't enough
- **The [N] parts** and the mistake most teams make in each
- **A copy-paste template** you can fill in this afternoon

## [Framework] in one picture
[Table or diagram: Part | What it answers | Signal you got it right]

## Part 1: [Claim-style heading]
[What it is] → [Common mistake] → **Do this:** [action]
... (repeat per part)

## What it looked like at [Client/Company]
[Before numbers] → [What we changed] → [After numbers]

## Copy this
[Template table]

**Where I stand:** [Your verdict + boundary condition].

[Self-diagnostic question]?

P.S. [Next asset / offer / event]
```

## T2 — Hands-on Build (repo / workflow / prompt giveaway)
*Derived from:* "The GTM Repository" (125♥), "Context Engineering" (109♥), "Content Engineering" (72♥), "Grok Bot for GTM", "Hands On: RevOps Workflows"

| Beat | Words | Content |
|---|---:|---|
| Hook | 80 | Hype paradox: "Everyone talks about X, few harvest the value" |
| Stakes | 80 | Productivity vs reinvention. Most people use it to do the same thing faster |
| Promise | 60 | Bullets + "you'll get a [repo/template] to copy" |
| Setup | 150 | Prereqs, structure, "think of the objective first" |
| Build steps | 600 | 4–7 steps, each with a screenshot/code block/prompt |
| Best practices | 200 | → arrow list of learnings, including where it broke |
| Fair advice | 60 | Limits, what's still beta, review requirements |
| Close | 80 | "What's the first workflow you'd hand to an agent?" |

```markdown
# [Build Your {System}: {Outcome} (Even If You Don't Code)]

[Tool/trend] [proof of hype stat]. Yet it feels like everybody is talking about it, and only a few are getting real value.

Most people use it to do the same thing they always did, faster. That's productivity. The real win is [reimagining process].

**What you'll get:**
- **How to structure** [repo/context] before an agent builds anything
- **The [N] workflows** I run every week, with prompts
- **A [template/repo] to copy**: [link]

## Step 1: [Objective first]
## Step 2: [Context]
## Step 3: [Build]
## Step 4: [Test with success criteria]
## Step 5: [Run on a schedule / hand off]

→ **[Learning 1]**
→ **[Learning 2]**
→ **[Where it broke and the fix]**

**Fair advice:** [limits].

What's the first workflow you'd hand to an agent?
```

## T4 — Mini Research / Data Report
*Derived from:* "I analyzed 199 pieces of LinkedIn content", "LinkedIn Mega Moodboard: 3,073 Posts", "Data From 195 Companies", "The 2026 State of GTM Engineering"

Rule: **show the sample before the insight.** ("If you are anything like me, you'll want to learn more about the sample immediately.")

```markdown
# I [Analyzed/Audited/Surveyed] [N] [Things]. Here's What's Actually Working.

Every [period], I [research ritual]. This time I'm sharing it.

**Why I do this:** [algo changes / generic studies lack vertical tactics / "because it matters to me"].

**The sample:**
- [N] [items], from [source], [date range]
- Selection criteria: [...]
- Limits: [...]

Still here? Great. Here are my **top [5] takeaways**. Some of them are a bit spicy.

## 1. [Finding as claim] — [stat]
[Evidence] → **What to do:** [action]
... ×5

## What surprised me
## What I'm changing in my own [work] because of this

Which finding matches what you're seeing? Which one doesn't?
```
